# Multi-branch support, barcode scanning, mobile responsive polish, and final QA hardening

Adds four pillars to StockFlow in a single phase: a multi-branch data model with context-aware filtering, html5-qrcode camera-based barcode scanning wired into Products/StockMovements/SalesOrders/Receiving, a mobile-first responsive overhaul (bottom tab bar, card-view DataTable, PWA manifest, safe-area CSS), and QA polish (ErrorBoundary per route, useDocumentTitle, 404 suggestions, aria-labels, console.log cleanup). The branch system introduces `BranchContext` + `BranchSwitcher` in the top nav, backed by Supabase tables (`branch_settings`, `user_branch_access`) and migration 008. The barcode generator produces deterministic SVG placeholders rather than real Code 128/EAN rendering, which is fine for display but won't scan correctly from printed labels.

Watch for: Branch filtering is plumbed but **never actually applied** to any data query — switching branches currently has no effect on what data the user sees (confirmed). RLS policies on the new tables grant blanket authenticated access for all operations (confirmed). The barcode scanner module-level singleton (`scannerInstance`) can leak if multiple `BarcodeScanner` components mount simultaneously (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

The branch subsystem is structurally complete — context, provider, switcher UI, CRUD hooks, migration — but the last-mile wiring is missing: no existing query (products, stock movements, orders) calls `applyBranchFilter`, so the branch switcher is cosmetic. This is the blocking gap.

Barcode scanning integrates html5-qrcode behind a Sheet-based viewfinder with a polished UX (beep, animated line, result card). The scanner service uses a module-global singleton which works for the current single-scanner UX but will break if the component ever mounts concurrently. The barcode generator is a visual placeholder — printed labels won't scan.

The mobile polish delivers card-view DataTable below 768px, a bottom tab bar with scroll-hide, PWA manifest, and safe-area insets. However, the MobileNav scroll-hide listens on `window.scroll` while the actual scroll container is a Radix `<ScrollArea>` — the hide logic likely never fires (possible).

RLS on the two new tables (`branch_settings`, `user_branch_access`) allows any authenticated user to perform any operation, defeating the purpose of branch isolation.

The ErrorBoundary wraps every route and isolates crashes per-page, but exposes raw `error.message` to end users in production, which could leak internal details (likely).

## Branch context plumbing without data filtering

`BranchContext` stores the active branch ID in React state and localStorage. `BranchSwitcher` renders a dropdown of active branches fetched via `useActiveBranches`. The `applyBranchFilter` helper is ready to augment any Supabase query builder:

```ts
export function applyBranchFilter<T extends { eq: (column: string, value: string) => T }>(
  query: T,
  branchId: string | null,
  column: string = 'branch_id'
): T {
  if (!branchId) return query;
  return query.eq(column, branchId);
}
```

Zero call sites exist for this function outside the barrel export. The actual inventory/sales/CRM queries never incorporate the branch filter. A user switching to "Branch A" sees exactly the same data as "All Branches." This is the only architectural gap that makes the branch feature non-functional.

## RLS grants blanket authenticated access

Migration 008 creates policies like:

```sql
CREATE POLICY "Auth manage branch settings" ON branch_settings FOR ALL USING (auth.role() = 'authenticated');
CREATE POLICY "Auth manage branch access" ON user_branch_access FOR ALL USING (auth.role() = 'authenticated');
```

Any logged-in user can modify any branch's settings or grant themselves admin access to any branch. The RLS should restrict mutations to users with `manager` or `admin` access_level for the target branch, and read access should be scoped to the user's assigned branches (unless they're a super-admin).

## Scanner singleton lifecycle

`src/services/barcode/scanner.ts` maintains a single `let scannerInstance: Html5Qrcode | null`. The `startScanner` function calls `await stopScanner()` before creating a new instance. The risk emerges from the `BarcodeScanner` component's `useEffect`:

```ts
useEffect(() => {
  if (open) {
    const timer = setTimeout(() => { initScanner(); }, 300);
    return () => clearTimeout(timer);
  } else {
    stopScanner().catch(() => {});
    ...
  }
}, [open]);
```

If the Sheet unmounts and remounts quickly (e.g., double-tap on mobile), the 300ms timeout from the first mount may fire after `stopScanner` from the unmount, re-starting a scanner that nobody owns. The cleanup clears the timeout only for the current effect cycle, not for cross-mount races. In practice this manifests as a camera LED staying on after the sheet closes.

## Barcode generator produces display-only output

`generateBarcode` builds an SVG by iterating character codes and drawing bars at positions determined by `(charCode * (i + 1)) % 2`. This encodes no real symbology. The `ProductDetail` page renders this and offers a "Print Barcode Label" button — a warehouse worker printing this label would get a non-scannable barcode. The QR generator has the same issue: decorative pattern with finder corners but no QR encoding.

If print-and-scan is a requirement, JsBarcode (for linear barcodes) or qrcode-generator (for QR) would produce standards-compliant output.

## MobileNav scroll-hide targets wrong scroll container

`MobileNav` attaches a `scroll` listener to `window`, but the app renders content inside `<ScrollArea>` (Radix scroll area) which scrolls an internal viewport div, not the window. `window.scrollY` remains 0, so `setVisible(false)` never triggers. The nav bar stays permanently visible regardless of scroll position. To fix, the scroll listener needs to target the ScrollArea's viewport element (available via a ref on the Radix component).

## ErrorBoundary exposes raw error messages

The fallback UI renders `this.state.error?.message` directly:

```tsx
<p className="text-sm text-muted-foreground mb-6">
  {this.state.error?.message || 'An unexpected error occurred...'}
</p>
```

Library errors and Supabase errors can include internal URLs, table names, or stack fragments. Gate the raw message behind a `import.meta.env.DEV` check and show only the generic fallback in production.

## DataTable mobile card renders all columns

The mobile card view iterates `columns` unconditionally — columns that use `className: 'hidden md:table-cell'` to hide on smaller screens in table mode will now appear in every card. For tables with many columns this produces verbose cards. Consider a `mobileVisible` flag on the column definition or filtering out columns marked hidden.

## PWA manifest uses SVG icons

The manifest declares SVG icons at 192 and 512. Chrome on Android requires raster images (PNG/WebP) for home screen icons and splash screens — SVG icons won't render there. iOS also requires apple-touch-icon as a PNG `<link>`. Add raster fallbacks if installability is a goal.
