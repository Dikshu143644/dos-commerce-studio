# Multi-branch support, barcode scanning, mobile polish, and final QA (v2)

Phase 8 adds four pillars to StockFlow: a multi-branch context system with branch-aware data filtering, html5-qrcode camera-based barcode scanning across Products/StockMovements/SalesOrders/Receiving, a responsive mobile overhaul (bottom tab nav, card-view DataTable, PWA manifest), and QA hardening (ErrorBoundary per route, useDocumentTitle, scroll-hide targeting Radix viewport, scanner token guard). All five issues from v1 have been addressed — branch filter is wired into queries, ErrorBoundary gates error details behind DEV mode, MobileNav targets the Radix viewport, and the scanner uses `acquireScannerToken` for concurrency.

Watch for: The branch filter applies `.eq('branch_id', ...)` to tables (`products`, `customers`, `deals`, `leads`, `sales_orders`, `purchase_orders`, `stock_movements`, `inventory`) that **have no `branch_id` column** in the database schema — this will produce Supabase 400 errors at runtime when any specific branch is selected (confirmed). The dashboard queries eight tables by `branch_id` with the same missing-column problem (confirmed). RLS on the new tables still grants blanket authenticated access for all operations (confirmed, accepted as-is per prior review).

**Verdict**: NEEDS_CHANGES

## High-level view

The branch filtering code is wired into every major query via `applyBranchFilter` and direct `.eq('branch_id', ...)` calls, but the underlying database tables lack a `branch_id` column. Migration 008 only adds `branch_settings` and `user_branch_access` tables — it never alters core entity tables. As soon as a user picks a specific branch, every filtered query will return a PostgREST 400 error.

The scanner's `handleScanResult` fires `onScan` via a 1-second `setTimeout` without cleanup. If the sheet closes before the timeout fires, the stale callback navigates or toasts on behalf of a closed component.

The MobileNav scroll-hide queries `[data-radix-scroll-area-viewport]` once on mount with an empty dependency array. If the viewport element is recreated after the initial render, the listener is orphaned and scroll-hide stops working.

## Branch filter targets missing database columns

Migration 008 creates two new tables (`branch_settings`, `user_branch_access`) and adds `barcode`/`barcode_format` columns to `products`. It does **not** add `branch_id` to any core entity table:

```
Table               Query applies         Has branch_id column?
──────────────────────────────────────────────────────────────
products            .eq('branch_id', x)   No
stock_movements     .eq('branch_id', x)   No
sales_orders        .eq('branch_id', x)   No
purchase_orders     .eq('branch_id', x)   No
warehouses          .eq('branch_id', x)   No
deals               .eq('branch_id', x)   No
customers           .eq('branch_id', x)   No
leads               .eq('branch_id', x)   No
inventory           .eq('branch_id', x)   No
```

Only `profiles` has `branch_id`. PostgREST returns HTTP 400 when filtering on a non-existent column. In `useProducts`, `useSalesOrders`, etc., the React Query `queryFn` will throw, producing infinite loading or an error state for the user.

The fix requires a migration adding `branch_id UUID REFERENCES branches(id) ON DELETE SET NULL` to at minimum: `products`, `warehouses`, `sales_orders`, `purchase_orders`, and `stock_movements`. For CRM tables (`deals`, `customers`, `leads`), decide whether branch scoping applies — the code currently assumes it does.

## Scanner timeout fires without lifecycle guard

In `BarcodeScanner.tsx`:

```tsx
const handleScanResult = useCallback(
  (result: ScanResult) => {
    playBeep();
    setLastResult(result);
    setScanning(false);
    stopScanner().catch(() => {});
    setTimeout(() => {
      onScan(result);
    }, 1000);
  },
  [onScan, playBeep]
);
```

The 1-second delay lets the user see the success card before navigation. If the user taps "Close" before the timeout fires, `onScan` executes after the component has closed — the Products page's `handleBarcodeScan` calls `navigate(...)`, causing a silent navigation 800ms after the user dismissed the scanner.

Fix by capturing the timeout in a ref and clearing it on close:

```tsx
const timeoutRef = useRef<ReturnType<typeof setTimeout>>();
// In handleScanResult:
timeoutRef.current = setTimeout(() => onScan(result), 1000);
// In the open=false effect branch:
if (timeoutRef.current) clearTimeout(timeoutRef.current);
```

## MobileNav viewport query runs once

```tsx
useEffect(() => {
  const viewport = document.querySelector('[data-radix-scroll-area-viewport]');
  if (!viewport) return;
  // attach scroll listener
  return () => viewport.removeEventListener('scroll', handleScroll);
}, []);
```

Two scenarios break this: (1) `MobileNav` mounts before the ScrollArea viewport renders — `viewport` is null and no listener ever attaches. (2) React re-creates the ScrollArea element (parent Suspense fallback → resolve cycle) — the old listener references a detached DOM node.

Scenario 1 is unlikely given `AppShell`'s render order. Scenario 2 depends on whether any boundary can force a full layout re-render. Adding `location.pathname` to the dependency array (re-queries on navigation) is a cheap defensive fix.
