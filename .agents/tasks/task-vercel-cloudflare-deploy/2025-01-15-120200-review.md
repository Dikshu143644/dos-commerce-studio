# Vercel + Cloudflare Workers deployment (v3)

All twelve issues from v1 and v2 have been resolved. Webhook signature verification uses `crypto.subtle` HMAC-SHA256 with constant-time comparison. Payment routes are behind JWT auth. The AI tool-call loop enforces a 25-second aggregate timeout. `sanitizeFilterValue` strips `%` and `_`. The service-role Supabase pattern is documented as intentional for single-tenant. Notifications return 202 with `stub: true`. CI documents the KV namespace prerequisite.

Watch for: The `CORS_ORIGIN` secret defaults to empty string, meaning a fresh deploy with no secret set only allows localhost origins — production requests from Vercel will be CORS-blocked until the operator sets this secret (confirmed). The `generate_excel_report` AI tool returns a preview array but no downloadable file; it's the only tool whose name implies a deliverable it doesn't produce (confirmed).

**Verdict**: APPROVED

## High-level view

The CORS middleware reads `CORS_ORIGIN` per-request but the secret is absent from `docs/deployment.md` Step 3. An operator following the guide will get CORS-blocked in production without a clear pointer to the missing config. `wrangler.toml` lists it in comments, but the deployment doc — the primary onboarding path — does not.

The `generate_excel_report` AI tool queries data and returns a JSON preview with `rowCount` and a 5-row sample, but produces no downloadable file. The dedicated `/excel/ai-generate` endpoint does produce a base64 file. The tool's `message` field tells the LLM "The file is ready for download" — causing the AI to confidently claim availability of something the user can't access from the chat response.

## CORS_ORIGIN deployment gap

In `workers/src/middleware/cors.ts`:

```typescript
const corsOrigin = c.env.CORS_ORIGIN || '';
const allowedOrigins = [
  'http://localhost:5173',
  'http://localhost:4173',
  ...corsOrigin.split(',').map((o) => o.trim()).filter(Boolean),
];
```

When `CORS_ORIGIN` is unset, only the two localhost entries remain. The `wrangler.toml` comments list `CORS_ORIGIN` as a required secret, but `docs/deployment.md` Step 3 ("Set Worker Secrets") lists only six secrets — `CORS_ORIGIN` is absent. The deployment checklist says "CORS headers are correct for your frontend domain" in the verification section, which an operator would fail without knowing why.

## AI tool `generate_excel_report` disconnect

In `workers/src/routes/ai-chat.ts`:

```typescript
case 'generate_excel_report': {
  const reportData = await generateReportData(supabaseClient, template, filters);
  data = {
    success: true,
    template,
    format,
    rowCount: reportData.length,
    message: `Generated ${template} report with ${reportData.length} rows in ${format} format. The file is ready for download.`,
    preview: reportData.slice(0, 5),
  };
  break;
}
```

The tool tells the AI "The file is ready for download" but the response contains no file. The dedicated `/excel/ai-generate` endpoint runs the same query and returns `{ file: base64, fileName, rowCount }`. Two options: have the tool call the actual endpoint internally and return the base64, or change the message to say "Here's a preview — ask the user to click Export to download the full file."
